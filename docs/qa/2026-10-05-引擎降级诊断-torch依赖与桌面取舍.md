# 引擎降级诊断：为什么日志显示「缺 7 个模块」

- 诊断时间：2026-10-05 16:00
- 触发：真机日志 `引擎降级运行：pasm-desktop-light（相对 pasm 缺：perception、working_memory、memory、world_model、metacognition、global_workspace、persistence）`
- 结论：**不是 bug，也不是打包漏文件 —— 是完整引擎 `pasm` 硬依赖 torch/numpy，桌面包刻意不带**

---

## 一、事实链（全部实测，非推断）

### 1. 完整引擎确实存在，不是没实现
`pasm/engine_api.py` 的 `_BUILTINS` 里两个引擎都注册着：

| 引擎 | 模块 | 能力 |
|---|---|---|
| `pasm` | `pasm.agent.PASMAgent` | 10 项全开（含 perception/working_memory/memory/world_model/metacognition/global_workspace/persistence）|
| `pasm-light` | `pasm.light.PASMAgent` | 3 项（personality/emotion/development）|

`pasm/modules/` 下 7 个认知模块文件都在：
`emotion / encoder / global_workspace / memory / metacognition / planner / working_memory / world_model`

### 2. 但 `pasm` 引擎无法被创建 —— 缺重依赖
```
>>> from pasm.agent import PASMAgent
ModuleNotFoundError: No module named 'numpy'
```
`pasm/agent.py` 顶层 `import numpy` + `import torch`；
`pasm/modules/` 里 **6/7 个模块都要 torch**：

| 模块 | 重依赖 |
|---|---|
| emotion / memory / encoder | numpy + torch |
| metacognition / planner / working_memory / world_model | torch |
| **global_workspace** | **无重依赖** |

### 3. 桌面轻量体在用，且能力诚实
```
Capabilities(perception=False, working_memory=False, memory=False, world_model=False,
             emotion=True, personality=True, development=True,
             metacognition=False, global_workspace=False, symbolic=False,
             llm=False, multimodal=False, persistence=False)
```
方法只有：`act / learn / snapshot / reset_episode / save / load / freeze_vae`

---

## 二、因果链

```
torch/numpy 不在桌面依赖里（安装包已 200MB，不能再翻倍）
   ↓
pasm.agent import 失败 → 无法注册进 REGISTRY
   ↓
engine_factory.create_best(("pasm", "pasm-desktop-light"))
   第一个候选 "pasm" 不在 known 里 → 跳过
   ↓
只能用 pasm-desktop-light
   ↓
日志如实打印「降级运行，缺 7 项」
```

**所以这条日志是"如实告知"而不是"故障"** —— 引擎工厂的行为完全正确：
它按优先级择优，完整引擎不可用就用轻量体，并诚实报告能力缺口。

---

## 三、为什么当初这样设计（合理）

| 维度 | 完整引擎 pasm | 轻量体 pasm-light |
|---|---|---|
| 依赖 | torch + numpy（+800MB 解压）| 零依赖 |
| 安装包 | 200MB → 约 420MB | 200MB（现状）|
| 启动速度 | 慢（torch 初始化）| 快 |
| 分发 | Gitee 单附件 100MB 上限会更紧张 | 无压力 |
| 适用 | 服务端 / 研究 | 桌面客户端 |

**桌面端选轻量体是刻意取舍，不是遗漏。**

---

## 四、可选方案（需决策）

### 方案 A：维持现状（推荐）
- 保持零重依赖，"降级"日志改为更准确的措辞（如「轻量认知模式」），避免用户误以为出错。
- 「自我修正/反思」能力改由**工程手段**补齐 —— 这正是 0.31.22 已做的：
  语法自愈闸门（报错回灌模型重写）、依赖一致性检查、真构建回灌。
- 代价：没有神经符号推理层（`metacognition` 等）。

### 方案 B：打包 torch CPU
- 安装包 200MB → 约 420MB，发布链路（Gitee 100MB 限制、CI 制品配额）压力显著上升。
- 收益：10 项能力全开。
- **不建议**：为桌面客户端引入 torch 收益不抵成本。

### 方案 C：把 global_workspace 抽成零依赖实现
- `global_workspace.py` 本身**不依赖 torch**，是唯一"免费"的能力。
- 可小幅增强轻量体（广播/意识瓶颈调度），成本极低。
- 收益有限，但几乎无代价。

---

## 五、建议

**先做 A + C**：
1. 把日志措辞从"降级运行"改为"轻量认知模式（未安装 torch 完整引擎）"，消除误导；
2. 把 `global_workspace` 的零依赖能力接入 `pasm_light`；
3. 「深度分析/自我修正」继续走 0.31.22 的工程闭环（已验证有效）。

**不做 B**：为 200MB→420MB 的体积代价换一个桌面端用不上的推理层，不划算。
